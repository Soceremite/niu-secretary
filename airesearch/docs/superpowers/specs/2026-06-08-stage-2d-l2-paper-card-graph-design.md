# Stage 2D L2 Paper Card And Graph Design

## Goal

Build the first L2 knowledge graph layer for AIResearch by converting already-ingested paperpipe papers into deterministic, auditable paper cards and graph records. This stage does not call an LLM and does not infer claims from paper text.

## Scope

Stage 2D.0 covers metadata-grounded extraction only:

- Create extraction run audit records.
- Create one paper card per paper with title, authors, year, venue, identifiers, artifact availability, source path, and extraction status.
- Create graph nodes for papers, authors, venues, identifiers, and artifacts.
- Create graph edges for `authored_by`, `published_in`, `has_identifier`, and `has_artifact`.
- Create provenance records linking every generated card/node/edge back to the source paper row or artifact row.
- Add CLI commands to extract, list, and export paper cards.

Out of scope for this stage:

- LLM extraction of methods, claims, datasets, benchmarks, limitations, or future-work statements.
- Vector embeddings or graph database migration.
- Full-text parsing beyond metadata and artifact inventory already synced from paperpipe.

## Architecture

SQLite remains the source of truth. `papers` and `paper_artifacts` are the inputs. `paper_cards`, `kg_nodes`, `kg_edges`, `kg_provenance`, and `extraction_runs` are the L2 outputs. Extraction is idempotent per paper: rerunning refreshes the paper card and replaces graph records generated by the deterministic extractor for that paper.

The extractor is deliberately conservative. It only emits facts that are directly present in existing metadata or artifact rows. Missing fields are represented as empty strings or empty JSON arrays instead of guessed values.

## Data Model

`extraction_runs` records batch execution counts and status.

`paper_cards` stores one row per paper key with structured metadata, artifact type list, source directory, extraction version, and timestamps.

`kg_nodes` stores typed nodes with stable keys. Node keys use prefixes such as `paper:<paper_key>`, `author:<normalized_name>`, `venue:<normalized_venue>`, `id:<type>:<value>`, and `artifact:<paper_key>:<artifact_type>`.

`kg_edges` stores directed typed relationships with stable uniqueness across source, target, and relation.

`kg_provenance` stores source table, source key, field name, and confidence for each generated card/node/edge. Confidence is `1.0` because this stage only copies explicit ledger facts.

## CLI

- `extract-paper-cards [--limit N] [--paper-key KEY]` runs deterministic L2 extraction.
- `list-paper-cards [--limit N]` prints compact paper cards.
- `export-paper-cards --out PATH` writes JSONL paper cards for downstream report generation.

## Error Handling

Malformed JSON in metadata fields is treated as empty data for that field, and the paper still receives a card with `status=partial`. Missing artifacts are allowed. A failed unexpected exception marks the extraction run as `failed` and preserves the error text.

## Testing

Unit tests cover schema creation, idempotent extraction, node/edge/provenance creation, CLI commands, export format, and partial metadata behavior. Existing tests must continue to pass.
