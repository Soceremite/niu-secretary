# AIResearch Native Layout Parser Implementation Plan

> **For agentic workers:** This plan documents the implemented direction after clarifying that AIResearch should borrow MinerU-like product ideas without installing or invoking MinerU.

**Goal:** Build a native AIResearch PDF layout parser that writes structured paper layout artifacts into the research library and feeds admin operations plus deep-reading evidence.

**Architecture:** Use PyMuPDF inside AIResearch to parse local paper PDFs from paperpipe. Store generated Markdown, content-list JSON, structure JSON, debug JSON, and extracted assets under `airesearch/data/layout`, then persist run status and block provenance in SQLite. Expose the parser through existing CLI, admin action, and `admin_jobs` queue paths.

**Implemented Scope:**

- Native parser module: `airesearch/src/airesearch/layout_parser.py`
- Persistence/orchestration: `airesearch/src/airesearch/layout_parse.py`
- SQLite tables: `paper_layout_runs`, `paper_layout_blocks`
- Artifact types:
  - `layout_markdown`
  - `layout_content_list`
  - `layout_structure_json`
  - `layout_debug_json`
  - `layout_asset`
- CLI:
  - `parse-layout`
  - `layout-status`
  - `parse-missing-layouts`
- Admin actions:
  - `airesearch.admin.paper.layout.detail`
  - `airesearch.admin.paper.layout.generate`
- Frontend: paper editor "版面解析" panel
- Deep reading: `layout_markdown` and `layout_block` visual candidates are included in the evidence pack when present.

**Non-Goals:**

- Do not install MinerU.
- Do not shell out to a MinerU executable.
- Do not expose external-parser-specific terms in API, frontend, or operator-facing docs for this implementation.
- Do not replace paperpipe ingestion.

**Next Quality Steps:**

- Add stronger table reconstruction from text geometry.
- Add formula grouping from line geometry and math-symbol density.
- Add optional layout visualization export generated by AIResearch itself.
- Improve image caption pairing by nearest text block and page geometry.
